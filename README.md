# L'Étoile de l'Est — Progressive Web App

PWA for **Complexe Touristique L'Étoile de l'Est**, Ain Abid, Constantine, Algeria.

This repository contains the **foundation slice** of the V1 build: a Next.js 14
PWA with bilingual FR/AR (RTL-aware), the design system, every spec'd route
shipping with realistic mocked content, the Supabase schema as SQL migrations,
and integration points wired to placeholders.

External services (Supabase, Twilio SMS OTP, BaridiMob, CIB, FCM, 360dialog
WhatsApp) are not connected — the app runs in mock mode when their env vars
are absent.

## Stack

- **Next.js 14** App Router · TypeScript strict
- **Tailwind CSS** + shadcn/ui primitives
- **@ducanh2912/next-pwa** (Workbox under the hood)
- **i18n**: server-first `[lang]` segment routing, JSON dictionaries, full RTL
- **Supabase** (`@supabase/ssr`) — three client factories with mock-mode fallback
- **Framer Motion** for booking step transitions and loyalty animations
- **react-hook-form + Zod** for form validation
- **qrcode** for QR generation · **@zxing/browser** for camera scanning

## Quick start

```bash
npm install
cp .env.example .env.local      # fill values as you wire each service
npm run dev                     # → http://localhost:3000
```

The root path redirects to `/fr` (French is the default; Arabic is at `/ar`).

## Mock mode

When `NEXT_PUBLIC_SUPABASE_URL` or `NEXT_PUBLIC_SUPABASE_ANON_KEY` is unset,
the three Supabase clients in `lib/supabase/` return `null` and the API routes
log to console instead of writing to the database. The marketing pages already
read from `lib/data/mock.ts` so the UI is fully functional without any
backend. This is the default state of this slice.

To wire real Supabase, follow `supabase/README.md` and fill `.env.local`.

## Bilingual implementation

- Routes carry the locale: `/fr/...` and `/ar/...`.
- `middleware.ts` detects `Accept-Language` on first hit and redirects to a
  locale-prefixed path.
- `<html lang dir>` flips for Arabic. Tailwind logical properties (`ms-*`,
  `me-*`, `ps-*`, `pe-*`, `text-start`, `text-end`) keep layouts correct in
  both directions.
- Number formatting uses `Intl.NumberFormat('ar-DZ')` for Arabic so prices
  render in Eastern Arabic-Indic numerals (spec §10.5).

## PWA

- Manifest: `public/manifest.webmanifest`.
- Service worker: generated by `@ducanh2912/next-pwa` during `next build`.
- Runtime caching:
  - **CacheFirst** for Google Fonts and the icon set
  - **StaleWhileRevalidate** for images
  - **NetworkFirst** with 10s timeout for `/api/*`
  - **NetworkFirst** with 5s timeout + offline fallback for HTML
- Offline scenarios:
  - `/compte/qr-checkin` works offline — the QR is generated client-side from
    cached booking data (stored in localStorage on first view).
  - `/offline` is the fallback page when navigation fails entirely.

The PWA is disabled in `next dev` (per `next.config.mjs`). To test it, run
`npm run build && npm start` and open DevTools → Application → Service Workers.

## What's next (V1 launch)

Per spec §11, V1 also requires:

- **Supabase Auth phone OTP** via Twilio — flip `NEXT_PUBLIC_SUPABASE_*`, then
  add a `/auth/sign-in` route using `signInWithOtp({ phone })`.
- **BaridiMob manual confirmation** — payment webhook is stubbed in
  `app/api/webhooks/payment/route.ts`. Wire the admin "Marquer payé" action in
  `/admin/reservations` to a Supabase RPC.
- **WhatsApp confirmations** via 360dialog — add a server action that posts
  the message template `booking_confirm_fr` after `bookings.status = confirmed`.
- **Loyalty redemption transactions** — currently the wizard subtracts the
  discount but does not insert a `loyalty_transactions` row.
- **Real images** in `public/images/` — current cards use SVG-encoded gradients
  as placeholders. Replace with WebP photos uploaded to Supabase Storage.
- **Real PWA icons** — `scripts/gen-icons.mjs` produced a star-on-forest
  placeholder. Replace with brand artwork before public launch.
